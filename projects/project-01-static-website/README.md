# 📁 Project 01 — Static Website with S3, CloudFront & Route 53

## 🎯 Goal

Deploy a static website to AWS using S3 as the origin, CloudFront as the CDN, and Route 53 for custom DNS. By the end you'll have a live, HTTPS-secured website served globally.

## 🏗️ Architecture

```
User
 │
 ▼
Route 53 (DNS)
 │  A/Alias record → CloudFront
 ▼
CloudFront Distribution
 │  Origin → S3 Bucket (private, OAC)
 ▼
S3 Bucket (static files)
```

## 🛠️ AWS Services

| Service | Role |
|---------|------|
| **S3** | Store and serve static website files |
| **CloudFront** | Global CDN, HTTPS termination, caching |
| **Route 53** | Custom domain DNS management |
| **ACM** | Free SSL/TLS certificate (us-east-1) |

## 📋 Step-by-Step Plan

### Step 1 — Build the Static Site
- [x] Build personal portfolio using Astro
- [ ] Output static build with `npm run build` (`dist/`)

### Step 2 — Set Up S3
- [ ] Create an S3 bucket (name it your domain, e.g. `my-site.com`)
- [ ] **Do NOT** enable public access — we'll use CloudFront OAC
- [ ] Upload website files to the bucket
- [ ] Explore bucket versioning

### Step 3 — Request an SSL Certificate (ACM)
- [ ] Go to **AWS Certificate Manager** in `us-east-1` (required for CloudFront)
- [ ] Request a public certificate for your domain (`*.yourdomain.com`)
- [ ] Validate via DNS (Route 53 can auto-create the CNAME record)

### Step 4 — Create a CloudFront Distribution
- [ ] Set origin to the S3 bucket using **Origin Access Control (OAC)**
- [ ] Attach the S3 bucket policy generated by CloudFront
- [ ] Set default root object to `index.html`
- [ ] Enable HTTPS (redirect HTTP → HTTPS)
- [ ] Set custom error response: 404 → `/404.html`
- [ ] Attach the ACM certificate

### Step 5 — Configure Route 53
- [ ] Create a hosted zone for your domain
- [ ] Add an **Alias A record** pointing to the CloudFront distribution
- [ ] (Optional) Add `www` → naked domain redirect

### Step 6 — Test & Iterate
- [ ] Visit your domain and verify HTTPS works
- [ ] Test cache behavior: update a file, create a CloudFront **invalidation**
- [ ] Experiment with cache TTL settings

### Step 7 — CI/CD (Bonus)
- [ ] Create a GitHub Actions workflow to sync S3 on push to `main`
- [ ] Automatically invalidate CloudFront cache after deploy

## 🔑 Key Concepts to Understand

- **OAC vs OAI** — Origin Access Control (newer) vs Origin Access Identity (legacy)
- **Cache behaviors** — how CloudFront decides what to cache and for how long
- **Invalidations** — how to purge cached content (first 1000/month are free)
- **Alias records** — Route 53-specific DNS records that map to AWS resources
- **ACM certificate region** — must be `us-east-1` for CloudFront
